# 技术架构

一个 Tauri 2 应用同时产出 Windows 桌面端和安卓端：播放、曲库和歌词逻辑在 Rust，界面是 WebView 里的 React。

## 产品边界

- **完全离线。** 不申请网络权限，不下载歌词或封面，没有账号和同步。
- **只播放本地文件。** 导入把音频和配对歌词收进曲库。确认移除后删除曲库里的这对文件。
- **安装包不带曲库。** 用户通过导入添加歌曲；仓库根的 `assets/` 只用于开发预览和手动测试，不进 git，不进安装包。
- **界面以现有实现为准。** 经用户确认、需要保持的界面决定见下文[界面约定](#界面约定)；可检查的行为由测试承接。改动外观或布局前先问用户。

## 技术选型

| 部分         | 选择                                                                | 理由                                                                                                                 |
| ------------ | ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 应用框架     | Tauri 2（桌面 Windows + 安卓）                                      | 用系统 WebView，不捆绑浏览器内核，安装包和内存占用小；一套代码出两端                                                 |
| 界面         | React + TypeScript + Vite                                           | 沿用仓库 [web tsconfig](../internal/tsconfig/web.json) 和 Vitest                                                     |
| 音频         | Rust：symphonia 解码，cpal 输出                                     | WebView 音频做不到独立升降调；安卓后台时 WebView 会被挂起，播放必须在 WebView 之外；两端行为一致，且能离线渲染做测试 |
| 倍速与升降调 | 自研 WSOLA 时间伸缩 + 线性插值重采样（与 SoundTouch 同类），纯 Rust | 不引入 C/C++ 依赖，安卓交叉编译简单、体积小；实现在 `Stretcher` 接口之后，音质不够时可换库而不影响调用方             |
| 标签与封面   | Rust 读取 mp3（ID3）和 ogg（Vorbis 注释）的内嵌封面                 | 与解码同在 Rust，界面只拿图片地址                                                                                    |
| 持久化       | 应用数据目录下的 JSON 文件，先写临时文件再替换                      | 数据只有曲库条目、列表顺序和几项设置，用不上数据库                                                                   |
| 安卓平台能力 | 自建 Tauri 插件（Kotlin）                                           | 前台服务、通知栏控制、音频焦点、文件选择和持久授权都只能在 Kotlin 侧完成                                             |

解码格式至少覆盖 mp3 和 ogg（Vorbis），这是现有曲库的全部格式；完整支持列表以 `music-audio` 启用的 symphonia 特性为准。安卓的音频输出经 cpal 使用 oboe（C++），`music-audio` 的构建脚本为它静态链接 NDK 的 libc++，否则应用加载原生库时崩溃。

## 模块划分

```
Cargo.toml                 # Rust workspace
packages/                  # 与 TS 包同在一处，各带只含脚本的 package.json
├── music-core/            # 曲库、文件名解析、导入配对、LRC 解析、播放列表与模式、持久化
├── music-audio/           # 解码、输出、倍速与升降调；可离线渲染到内存
└── tauri-plugin-playback/ # 安卓：前台服务、通知栏、音频焦点、文件选择（Kotlin）
apps/player/               # Tauri 应用 @music/player
├── src/                   # 界面：桌面和移动两套布局，共享状态与组件
├── src-tauri/             # 外壳：命令与事件、窗口（含桌面歌词）、接入插件
└── e2e/                   # 桌面端到端测试
fixtures/music/            # 各层测试共用的短音频和歌词，由脚本生成，进 git
```

依赖方向：`apps/player/src-tauri` → `music-core`、`music-audio`、`tauri-plugin-playback`；`music-core` 和 `music-audio` 互不依赖，也不依赖 Tauri，可以单独测试。

## 协作方式

**播放状态只有一份，在 Rust。** 外壳持有播放器：播放列表及顺序、当前歌曲、播放与暂停、模式、音量、倍速、升降调。界面只是它的投影：

- 界面 → Rust：通过 `invoke` 发命令（播放、跳转、切歌、改模式、调节、排序、移除、导入）。
- Rust → 界面：状态变化时发完整快照；播放中按固定频率发进度，界面在两次进度之间按帧插值，用于歌词逐字着色和进度条。插值进度单独订阅（`usePlaybackPosition`），只让进度条、时间和歌词这类小组件按帧重渲染；布局和播放队列只随状态快照更新。
- 桌面歌词窗口、安卓通知栏订阅同一份状态，所以它们和主界面不会不同步。

安卓切到后台后，Rust 继续播放当前歌曲。回到前台时，界面向 Rust 请求最新快照。输出设备首次需要时才打开。安卓暂停时释放设备并保留进度，继续播放时从该位置重新载入。

**歌词。** `music-core` 解析 LRC（多时间标签、`[offset]`，UTF-8 失败时按 GBK 解码）；界面切歌时通过命令取当前歌曲的歌词，当前行由界面根据进度计算。没有歌词的歌曲由界面显示“纯音乐，请欣赏”。

**导入。** 歌曲和 `.lrc` 按去掉扩展名的文件名配对，歌手和歌名来自文件名“歌手 - 歌名”。按包含扩展名的文件名去重，忽略大小写和主文件名首尾空格。同名文件保留先导入的版本。没有配对歌曲的歌词留在原处。

**桌面歌单。** 曲库保存全部已导入歌曲，自建歌单保存曲库歌曲的有序引用，播放队列保存当前播放顺序；三者随会话保存在 Rust。播放歌单时以歌单内容替换队列，之后调整队列或从队列移除歌曲不改变歌单和曲库。从歌单移出歌曲不删除文件；从曲库确认移除歌曲时，所有歌单中的引用一并移除，并按下文规则处理文件。旧会话的播放列表同时作为初始曲库和队列恢复。桌面从“全部音乐”导入只添加到曲库，从队列入口导入同时追加到队列。

外壳负责曲库文件。Windows 使用当前可执行文件所在目录，安卓使用应用私有数据目录，两端用 `assets/music` 保存音频、`assets/lysis` 保存歌词。曲库和会话写入成功后才移走源文件。源位置不允许删除时保留原件并提示。旧会话可以照常读取外部路径和已有授权的安卓 URI，移除旧条目时保留外部文件。

**封面。** 内嵌封面由外壳通过自定义协议提供给界面，不经 IPC 传图片数据。桌面端没有内嵌封面时回退到曲库 `assets/img` 里与歌曲同名的图片（导入时跟随源目录 `img/` 一同入库，移除歌曲时一并删除）；两者都没有时界面用歌名首字生成字封。

**平台差异只在外壳和插件里。**

| 能力     | 桌面                             | 安卓                             |
| -------- | -------------------------------- | -------------------------------- |
| 桌面歌词 | 透明、置顶、可拖动的独立窗口     | 无                               |
| 后台播放 | 窗口最小化即可                   | 前台服务 + 媒体通知              |
| 系统打断 | 无                               | 见下文“安卓系统行为”             |
| 导入     | 文件对话框、拖放到窗口           | 系统文件选择器（文件或文件夹）   |
| 布局     | 全窗口歌词 + 右侧播放队列 + 底栏 | 首页播放列表 + 播放页 + 底部弹层 |

界面按平台选择布局，不按窗口宽度切换。

**安卓系统行为。**

- **音频焦点：** 通知提示音等“可降低音量”的打断时继续播放，由系统压低音量；来电、语音消息等短暂打断时暂停，焦点回来后自动继续；其他音乐应用开始播放时暂停，不再自动继续。耳机拔出时暂停。
- **返回键：** 由界面接管，逐级返回：取消移除确认 → 关闭弹层 → 回到列表 → 清空搜索 → 把应用退到后台。不能让系统结束 Activity：Tauri 会把它当作关闭最后一个窗口而退出整个进程，音乐随之停止。
- **系统栏：** 安卓 15 起应用绘制到系统栏下面。内容让开状态栏和导航栏；深色播放页不铺到状态栏下，状态栏区域保持应用的浅色底，系统时间和图标始终看得清。
- **通知栏和锁屏卡片：** 只在播放状态真正变化时（播放、暂停、跳转、切歌、改倍速）同步位置、时长和倍速，进度由系统自行推算。

## 界面约定

以下界面决定经用户确认，修改前先问用户：

| 位置          | 约定                                                                                       |
| ------------- | ------------------------------------------------------------------------------------------ |
| 桌面播放队列  | 与舞台同一背景，不另起深色面板；封面行 64px、紧凑行 40px；细滚动条无箭头；滚轮平滑缓动     |
| 桌面队列搜索  | 匹配处用柔和蓝色、不加粗；搜索框和工具按钮的焦点用底色表示，不画白框                       |
| 收起/展开队列 | 歌词行从原位置平滑移到新位置（与队列滑动同节奏），不瞬间跳到居中                           |
| 桌面底栏      | 升降调/倍速按钮为“⋮”，倍速不为 1.0 时显示如“1.2X”的角标；底栏右侧不显示倍速和音调文字      |
| 升降调/倍速   | 两端都没有“恢复正常”；升降调每侧 5 档（-5 到 +5），与倍速 0.5–1.5 每侧 5 档对应            |
| 桌面歌词窗口  | 两行都居中，交替显示；中等字重、细深色描边、白到青的着色；超长的当前行跟随演唱位置横向平移 |
| 安卓播放页    | 状态栏区域保持浅色底（见上文“安卓系统行为”）                                               |

## 测试分层

先写测试再实现。要长期保证的行为写成可重放的测试，按层分工：

| 层       | 位置                            | 工具                                                       | 承接                                                                                          |
| -------- | ------------------------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 单测     | `packages/music-*`              | `cargo test`                                               | 文件名解析、配对、LRC、播放模式与顺序、持久化；音频离线渲染后检查时长（倍速）和主频（升降调） |
| 组件     | `apps/player/src/**/*.test.tsx` | Vitest + Testing Library，`@tauri-apps/api/mocks` 模拟 IPC | 界面结构、交互、状态显示                                                                      |
| 桌面 e2e | `apps/player/e2e/desktop`       | WebdriverIO + tauri-driver（Windows）                      | 真实应用的完整流程：导入、播放、拖动排序、桌面歌词、重启恢复                                  |
| 构建检查 | 仓库脚本                        | 读取构建产物                                               | 安装包体积、安卓无网络权限、Tauri 未开放网络能力                                              |
| 人工     | —                               | 实际运行；安卓用真机                                       | 视觉还原、实际听感；安卓的文件选择、后台与锁屏播放、通知栏控制、音频焦点                      |

测试素材用 `fixtures/music/` 里脚本生成的几秒正弦波音频，以及 UTF-8、GBK、无歌词、无封面、文件名无“ - ”等歌词与文件样本。`assets/` 不进 git，CI 拿不到，测试不得依赖它。

各层的运行命令见[测试说明](testing.md)。
