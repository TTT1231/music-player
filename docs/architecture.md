# 技术架构

一个 Tauri 2 应用同时产出 Windows 桌面端和安卓端：播放、曲库和歌词逻辑在 Rust，界面是 WebView 里的 React。

## 产品边界

- **完全离线。** 不申请网络权限，不下载歌词或封面，没有账号和同步。
- **只播放本地文件。** 导入只记录文件位置，不复制文件；从播放列表移除不删除磁盘上的文件。
- **安装包不带曲库。** 用户通过导入添加歌曲；仓库根的 `assets/` 只用于开发预览和手动测试，不进 git，不进安装包。
- **界面以设计原型为准。** 原型在 `design/preview/`（本地，不进 git），可检查的行为写在[验收清单](acceptance.md)。偏离原型前先问用户。

## 技术选型

| 部分         | 选择                                                            | 理由                                                                                                                 |
| ------------ | --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 应用框架     | Tauri 2（桌面 Windows + 安卓）                                  | 用系统 WebView，不捆绑浏览器内核，安装包和内存占用小；一套代码出两端                                                 |
| 界面         | React + TypeScript + Vite                                       | 沿用仓库 [web tsconfig](../internal/tsconfig/web.json) 和 Vitest；设计原型本身就是 HTML，可直接移植                  |
| 音频         | Rust：symphonia 解码，cpal 输出，时间伸缩处理器负责倍速和升降调 | WebView 音频做不到独立升降调；安卓后台时 WebView 会被挂起，播放必须在 WebView 之外；两端行为一致，且能离线渲染做测试 |
| 标签与封面   | Rust 读取 mp3（ID3）和 ogg（Vorbis 注释）的内嵌封面             | 与解码同在 Rust，界面只拿图片地址                                                                                    |
| 持久化       | 应用数据目录下的 JSON 文件，先写临时文件再替换                  | 数据只有曲库条目、列表顺序和几项设置，用不上数据库                                                                   |
| 安卓平台能力 | 自建 Tauri 插件（Kotlin）                                       | 前台服务、通知栏控制、音频焦点、文件选择和持久授权都只能在 Kotlin 侧完成                                             |

解码格式至少覆盖 mp3 和 ogg（Vorbis），这是现有曲库的全部格式；完整支持列表以 `music-core` 为准。

## 模块划分

```
Cargo.toml                 # Rust workspace
packages/                  # 与 TS 包同在一处，各带只含脚本的 package.json
├── music-core/            # 曲库、文件名解析、导入配对、LRC 解析、播放列表与模式、持久化
├── music-audio/           # 解码、输出、倍速与升降调；可离线渲染到内存
└── tauri-plugin-playback/ # 安卓：前台服务、通知栏、音频焦点、文件选择（Kotlin）
apps/player/               # Tauri 应用 @music/player
├── src/                   # 界面：桌面和移动两套布局，共享状态与组件
├── src-tauri/             # 外壳：命令与事件、窗口（含桌面歌词）、接入插件
└── e2e/                   # 桌面和安卓端到端测试
fixtures/music/            # 各层测试共用的短音频和歌词，由脚本生成，进 git
```

依赖方向：`apps/player/src-tauri` → `music-core`、`music-audio`、`tauri-plugin-playback`；`music-core` 和 `music-audio` 互不依赖，也不依赖 Tauri，可以单独测试。

## 协作方式

**播放状态只有一份，在 Rust。** 外壳持有播放器：播放列表及顺序、当前歌曲、播放与暂停、模式、音量、倍速、升降调。界面只是它的投影：

- 界面 → Rust：通过 `invoke` 发命令（播放、跳转、切歌、改模式、调节、排序、移除、导入）。
- Rust → 界面：状态变化时发完整快照；播放中按固定频率发进度，界面在两次进度之间插值，用于歌词逐字着色和进度条。
- 桌面歌词窗口、安卓通知栏订阅同一份状态，所以它们和主界面不会不同步。

这样安卓切到后台、WebView 被挂起时播放照常继续，回到前台后界面从快照恢复。

**歌词。** `music-core` 解析 LRC（多时间标签、`[offset]`，UTF-8 失败时按 GBK 解码），随歌曲一起交给界面；当前行由界面根据进度计算。没有歌词的歌曲由界面显示“纯音乐，请欣赏”。

**导入。** 歌曲和 `.lrc` 一起选择，按去掉扩展名的文件名配对，歌手和歌名来自文件名“歌手 - 歌名”。桌面端记录文件路径；安卓端记录文件选择器返回的 URI 并申请持久授权，播放时由插件打开文件、把文件描述符交给 Rust，Rust 侧始终只读普通文件句柄。

**封面。** 内嵌封面由外壳通过自定义协议提供给界面，不经 IPC 传图片数据；没有封面时界面用歌名首字生成字封。

**平台差异只在外壳和插件里。**

| 能力     | 桌面                             | 安卓                             |
| -------- | -------------------------------- | -------------------------------- |
| 桌面歌词 | 透明、置顶、可拖动的独立窗口     | 无                               |
| 后台播放 | 窗口最小化即可                   | 前台服务 + 媒体通知              |
| 系统打断 | 无                               | 音频焦点丢失、耳机拔出时暂停     |
| 导入     | 文件对话框、拖放到窗口           | 系统文件选择器（文件或文件夹）   |
| 布局     | 全窗口歌词 + 右侧播放队列 + 底栏 | 首页播放列表 + 播放页 + 底部弹层 |

界面按平台选择布局，不按窗口宽度切换。

## 测试分层

先写测试再实现。[验收清单](acceptance.md)每条标准都标注了由哪一层承接：

| 层       | 位置                            | 工具                                                       | 承接                                                                                          |
| -------- | ------------------------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 单测     | `packages/music-*`              | `cargo test`                                               | 文件名解析、配对、LRC、播放模式与顺序、持久化；音频离线渲染后检查时长（倍速）和主频（升降调） |
| 组件     | `apps/player/src/**/*.test.tsx` | Vitest + Testing Library，`@tauri-apps/api/mocks` 模拟 IPC | 界面结构、交互、状态显示                                                                      |
| 桌面 e2e | `apps/player/e2e/desktop`       | WebdriverIO + tauri-driver（Windows）                      | 真实应用的完整流程：导入、播放、拖动排序、桌面歌词、重启恢复                                  |
| 安卓 e2e | `apps/player/e2e/android`       | Appium（UiAutomator2 + WebView 上下文），模拟器            | 文件选择、后台播放、通知栏控制、重启后仍可播放                                                |
| 构建检查 | 仓库脚本                        | 读取构建产物                                               | 安装包体积、安卓无网络权限、Tauri 未开放网络能力                                              |
| 人工     | —                               | 对照设计原型                                               | 视觉还原、实际听感                                                                            |

测试素材用 `fixtures/music/` 里脚本生成的几秒正弦波音频，以及 UTF-8、GBK、无歌词、无封面、文件名无“ - ”等歌词与文件样本。`assets/` 不进 git，CI 拿不到，测试不得依赖它。

各层的运行命令在对应测试接入时写进[测试说明](testing.md)。
